# 启动降级 · 产品设计

## 问题

新机器下载不到最新版 get-pip.py，却拿到了旧版脚本；旧版 pip 在 Python 3.12 缺少 distutils，导致 pip 未安装。虽然 Python 已就绪且机器上有 ffmpeg，后端因缺 fastapi、uvicorn、httpx、pydantic 而直接退出。用户希望“依赖安装失败，也要启动”。

## 用户能得到什么

1. 首次下载便携 Python 后，即使 pip 引导失败也自动尝试修复，不把半装好的 Python 当作完整环境。
2. 不依赖 get-pip.py 的网络路径作为备援：从国内 pip 索引取得兼容的 pip wheel，放进项目内的便携 Python；不改系统 Python。
3. 若核心依赖仍不可用，启动一个只提供本机帮助页面与环境自检的临时服务，页面清楚说明“处理视频不可用”、实际缺失项和下一步，提供重试安装；绝不把降级页面伪装成可用的完整服务。
4. 若核心依赖已就绪，即使 ffmpeg 下载失败，也先启动主界面，并在页面/自检中明确提示视频处理受限；exiftool 缺失仍为可选项。
5. 核心依赖修复后重新双击启动即可恢复完整服务。诊断模式默认只允许本机访问，不因配置里开启 LAN 而对外暴露。

## 验收

- 旧版 get-pip.py 报 distutils 时能够通过 wheel 备援修复，并真正安装核心依赖。
- 人为模拟所有安装渠道失败时，浏览器仍能访问帮助页面，页面不允许误以为可以处理视频，重试失败不导致诊断服务消失。
- 已有核心依赖但没有 ffmpeg 时，完整界面可打开，自检和任务处理明确告知缺 ffmpeg。
