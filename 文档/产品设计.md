# VAIR · 视频 AI 重命名助手 — 产品设计

> 版本：v2（从高保真原型升级为可实际使用的完整产品）
> 日期：2026-11-15
> 上一版为纯前端模拟原型，本版目标是把整条流水线做成**真正能跑、能出活**的工具。

---

## 1. 产品定位

VAIR 是一款**本地离线优先**的视频素材批量重命名工具。用户把视频（或整个文件夹）交给它，它自动完成：

```
探测 → 抽帧 → 转写 → 合并 → 视觉大模型分析 → 重命名落盘
```

把「一堆无法检索的 `DJI_20240612_143022_0042.MP4`」变成「`20260612_1430_海边日落延时摄影空镜.mp4`」。

**这不是一个演示品。** 它必须能在用户自己的机器上，用用户自己的素材，跑出正确的结果。

### 与同类工具的差异

| 维度 | 常见做法 | VAIR 的做法 |
| --- | --- | --- |
| 识别依据 | 只看画面 | 画面关键帧 + 语音转写 + 原始文件名 + 录制时间，四路信息融合 |
| 模型部署 | 要求用户自备云端 API | **内置** llama.cpp + Qwen3.8-9B（视觉）+ Qwen3-ASR，开箱即用 |
| 联网要求 | 必须联网 | 默认全本地；API 转写是可选加速项，不是必需项 |
| 结果可控 | 直接改名，改错没法救 | 预览模式 + 命名审批 + 重命名记录，随时可回溯 |

## 2. 目标用户

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 视频创作者 | 拍摄结束批量归档 | 少操作、批量处理、名字能看懂 |
| 素材管理员 | 整理历史素材库 | 可检索、可审批、可回溯 |
| 后期团队 | 多人协作前统一命名 | 规则稳定、结果可控、日志清楚 |
| **拿到这个项目的人** | 想自己跑起来 | **一键装依赖、一键下模型，不用读文档** |

最后一行是本次新增的**一等公民**。项目要能被别人直接拿去用，而不是只有作者会跑。

## 3. 关键产品决策

### 3.1 内置 AI，开箱即用

用户机器上 `AI/` 目录已经放好了 llama.cpp（CUDA 版）、`Qwen3.8-9B` 的 GGUF 视觉模型和 `Qwen/Qwen3-ASR-0.6B`。后端启动时**自动拉起**这些服务，无需用户手动开终端。

- `llama-server.exe`（视觉大模型，默认 `127.0.0.1:8084`）
- Qwen3-ASR 的 Gradio 服务（语音转写，默认 `127.0.0.1:7867`）

设置页提供「AI 服务」面板：显示每个服务的**状态、端口、日志**，可单独启动 / 停止 / 重启。

服务不会白占显存：**整批任务落盘完成后自动关闭**（默认开启，可在设置里关掉）。
下次点「开始处理」时后端会先把它们拉起来再开工。服务崩溃时状态里直接给中文原因
（显存不足 / 内存不足 / 端口被占 / 模型缺失），而不是一句 `returncode=1`。

### 3.2 「一键补齐」——为别人着想

模型和依赖体积巨大（视觉模型 4.82 GB + mmproj 0.86 GB + ASR 1.75 GB + 对齐模型 1.71 GB +
llama.cpp 运行时 0.76 GB，合计约 10.4 GB），不可能入库。所以：

- 仓库只带**代码**，不带模型。
- 设置页有一个「**补齐 AI 依赖与模型**」按钮，点击后：
  1. 检查 `AI/` 目录结构，列出缺什么（用清单形式展示：llama.cpp 二进制 / 视觉模型 / mmproj / ASR 模型 / 对齐模型）
  2. 一键下载缺失项，**支持断点续传**（大文件必须能续）
  3. 下载走国内镜像（HF-Mirror / 清华源 / 阿里源），可在设置里切换
  4. 实时显示进度、速度、剩余时间
- 下载源、目标目录、是否覆盖，全部可在设置页配置。

**验收标准**：一个从没接触过这个项目的人，clone 代码 → 双击启动 → 点「补齐 AI 依赖」→ 等下载完 → 能跑出结果。

### 3.3 预览模式（安全阀）

批量改名是**破坏性操作**。预览模式下全流程照跑（探测、抽帧、转写、AI 分析全都真跑，耗时的推理一点不少），**唯独不落盘**：不重命名、不写 NFO/SRT、不改元数据。结果汇总在「命名审批」页让用户过目。

用户确认满意后关掉预览模式再跑一次。这是「放心交给引擎」的兑现方式。

### 3.4 命名审批（人工兜底）

AI 不是永远对。审批页逐条展示：

- 缩略图 / 原文件名（删除线）/ AI 建议新名（**可直接编辑**）
- 标签、置信度、处理耗时
- 单条通过 / 忽略，批量通过 / 忽略，操作后可撤销

未审批的条目**不会落盘**。用户点了「通过」才真正改名。

### 3.5 服务端持久化，前端无状态

上一版前端把状态存在浏览器内存里，刷新就没了。本版：

- 队列、任务、配置、审批、日志**全部在后端**。
- 前端只是视图。刷新、换浏览器、手机打开同一个地址，看到的都是同一份状态。
- 这就是 `lan` 开关的意义：手机连上同一个 Wi-Fi 就能查看进度、审批命名。

## 4. 功能清单

### 4.1 工作台

- 拖拽文件 / 拖拽文件夹 / 输入路径 / 原生文件选择器（`tkinter`，不受浏览器沙箱限制）
- 队列展示文件名、大小、时长；可单条移除、可清空
- **递归子文件夹**开关
- 开始 / 停止；预览模式开关
- 统计卡：成功 / 跳过 / 失败 / 平均耗时
- 总进度：百分比、当前文件、当前阶段、预计剩余时间

### 4.2 实时进度

- 五阶段流水线：探测 → 抽帧/转写（并行分支）→ 合并 → AI 分析 → 落盘
- 阶段节点随实际进度点亮，运行节点带脉冲，完成节点变绿
- 点击阶段展开该阶段指标与最近日志
- 单文件维度：当前文件在第几阶段、已耗时、预计剩余

### 4.3 命名审批

- 汇总：待审批 / 已通过 / 已忽略
- 每行：缩略图、原名、新名（可编辑）、标签、置信度
- 单条与批量操作，支持撤销
- 空状态引导

### 4.4 运行日志

- 级别筛选 ALL / DEBUG / INFO / WARN / ERROR
- 搜索、自动滚动、清空、导出
- 源文件日志（桌面版）
- 单文件推理时间线：模型名、帧数、字幕字数、端到端耗时

### 4.5 设置（本次重点「完善」）

保留玻璃风五分区导航，但把每个分区**补到能覆盖后端全部配置项**：

| 分区 | 覆盖内容 |
| --- | --- |
| **引擎与输入** | 递归子文件夹、Whisper 开关、API ASR 优先、GPU 加速、VAD 过滤、抽帧并发、关键帧数、最长边、转写语言、本地模型/设备/计算精度、转写并发 |
| **命名与输出** | 时间前缀、原名后缀、处理标记、跳过已处理、命名模板、日期格式、marker 字符串、NFO、SRT、ExifTool 元数据、分片 MP4 重封装、失败移入 `_failed`、预览模式 |
| **AI 与提示词** | provider、base_url、api_key、model、timeout、retry、max_tokens、temperature、top_p、强制 JSON、系统提示词、用户提示词、**连接测试**、AI 并发 |
| **系统与依赖** | 服务监听（局域网开关、监听地址、当前模式）、AI 服务管理（llama-server / Qwen3-ASR 启停与状态）、**一键补齐 AI 依赖与模型**、下载镜像（pip / HF）、CUDA 库自动补装、日志级别与日志文件、术语速查 |
| **术语表** | 术语 → 释义，注入提示词提升识别率 |

每个配置项都带 `?` 悬停解释（面向非技术用户）。

## 5. 状态模型

### 5.1 服务状态

| 状态 | 含义 |
| --- | --- |
| `stopped` | 未运行 |
| `starting` | 启动中（模型加载需要时间，视觉模型约 5–20 秒） |
| `running` | 就绪，可接受请求 |
| `error` | 启动失败，展示 stderr 尾部 |

### 5.2 任务状态

`idle` → `running` → `done` / `stopped` / `error`

### 5.3 单文件状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 排队中 |
| `running` | 处理中 |
| `review` | 已出结果，等待用户审批（预览模式或开了审批时） |
| `success` | 已重命名成功 |
| `skipped` | 已处理过，跳过 |
| `failed` | 失败，已移入 `_failed` |
| `canceled` | 用户中途停止 |

## 6. 关键交互

- `Ctrl/Cmd + K` 命令面板；`1–5` 切页；`Ctrl/Cmd + S` 保存设置
- 拖拽文件到窗口任意位置都可加入队列
- 配置文件改动**即时保存**（开关类）或点「保存修改」（文本类）
- 服务未就绪时点「开始处理」→ 提示并**自动拉起服务**，而不是报错
- 安装/下载类长任务：进度条 + 可取消 + 断点续传

---

## 7. 错误处理原则

1. **能自动修的不要问用户**：端口被占 → 换端口；CUDA 库缺失 → 自动补；模型没下 → 提示一键下。
2. **失败要能定位**：每个失败文件记录失败阶段 + 原始错误 + stderr 尾部，日志可导出。
3. **单个文件失败不中断整批**：记失败、移入 `_failed`、继续下一个。
4. **API 不可用不致命**：ASR API 连续失败自动回退本地；视觉 API 不可用则降级为「只用转写文本 + 文件名 + 时间」命名。

## 9. 验收标准

**功能**
1. 拖入一个真实 MP4 → 开始处理 → 产出带语义的文件名 + NFO + SRT + 元数据。
2. 预览模式下跑完整流程，磁盘上**一个字节都没变**。
3. 断网情况下，纯本地链路能跑通（视觉模型 + 本地 ASR）。
4. 关闭 `AI/` 里的模型，点「补齐 AI 依赖与模型」能下载回来并自动跑通。
5. 改设置 → 刷新页面 → 设置还在（存在后端 `config.json`）。
6. 中途停止任务 → 进度保留、已处理文件的结果不丢。
7. 手机连同一 Wi-Fi 打开 → 能看到进度、能审批。

**非功能**
8. 冷启动到可接受请求 < 30 秒（不含模型加载）。
9. 单文件端到端耗时在 12GB 显存机器上 < 90 秒（1080p / 3 分钟素材）。
10. 任意页面刷新状态不丢。
