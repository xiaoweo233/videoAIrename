## 1. 技术选型

| 项 | 选择 | 原因 |
| --- | --- | --- |
| 后端语言 | Python 3.10+ | ASR / 图像 / AI SDK 生态只此一家 |
| Web 框架 | FastAPI + Uvicorn | 原生 async、SSE 容易、类型清晰 |
| 实时推送 | SSE（Server-Sent Events） | 单向推送够用，比 WebSocket 简单、断线自动重连 |
| 持久化 | JSON 文件（`config.json` / `data/*.json`） | 无外部依赖，单机工具不需要数据库 |
| 并发 | `ThreadPoolExecutor` + `queue.Queue` | 全链路是阻塞的 subprocess / HTTP 调用，线程池最直接 |
| 前端 | 原生 HTML/CSS/ES2020，零构建 | 沿用现有玻璃风原型，保持 `file://` 可用 |
| AI 运行时 | 内置 llama.cpp（CUDA）+ Qwen3.8-9B + Qwen3-ASR | 开箱即用，不要求用户配云端 API |

**替代方案与否决理由**

- *SQLAlchemy + SQLite*：参考实现用了，但本项目任务状态不需要跨进程/跨会话查询，JSON 足够。否决。
- *Celery / RQ*：需要 Redis，单机工具引入太重。否决。
- *WebSocket*：需要处理重连、心跳、协议升级，SSE 一行 `EventSource` 搞定。否决。

## 3. 后端架构

### 3.1 启动顺序（有硬性依赖）

```
run.py
 ├─ 1. 解析 CLI 参数（--host --port --lan --no-install --selfcheck）
 ├─ 2. bootstrap.early_init()        # 必须在任何第三方 import 之前
 │      ├─ 建目录
 │      ├─ 重定向 TEMP / HF_HOME 到仓库内（不污染系统盘）
 │      ├─ 把 libs/ 注入 sys.path（零污染安装）
 │      ├─ 应用 pip / HF 镜像（写环境变量）
 │      └─ stdout/stderr 切 UTF-8（Windows 中文不乱码）
 ├─ 3. bootstrap.probe()             # 自检：ffmpeg/exiftool/依赖/CUDA/AI 目录
 ├─ 4. （可选）bootstrap.ensure()     # 缺依赖就装，缺模型就下（需 --install 或配置开启）
 ├─ 5. import uvicorn / api          # 此时才允许导入第三方
 └─ 6. services.start_all()           # 拉起 llama-server 与 Qwen3-ASR（后台线程）
```

第 2 步不可后移：`libs/` 注入必须在 `import fastapi` 之前，否则拿到的是系统里的旧版本。

### 3.2 目录根判定

`后端/app/paths.py` 由 `__file__` 反推：

```python
APP_DIR     = 后端/app
BACKEND_DIR = 后端
ROOT        = 后端/.. = 仓库根
```

所有配置里的相对路径都相对 `ROOT` 解析，用户换目录不用改配置。

### 3.3 数据流

```
用户拖入文件
   ↓ POST /api/items            （探测 + 入队）
engine：生产者线程
   ├─ media.probe()              ffprobe：时长/分辨率/creation_time/关键帧时间戳
   ├─ media.extract_frames()     ThreadPoolExecutor(frames.workers)
   │     └─ 逐时间点 ffmpeg -ss -frames:v 1 → JPEG 字节
   ├─ transcribe.run()           本地 faster-whisper 或远程 ASR
   ├─ 分片 MP4 检测与重封装        moov+moof → ffmpeg -c copy
   └─ push 到 queue.Queue
        ↓  N 个 AI 消费者线程（runtime.ai_workers）
   ├─ vision.analyze()           关键帧 + 转写 + 文件名 + 时间 → 视觉大模型
   │     └─ Anthropic / OpenAI 兼容 /v1/chat/completions
   ├─ naming.build_target()      模板渲染 → 合法化 → 去重
   └─ outputs.write()            NFO / SRT / exiftool（dry_run 时全部跳过）
        ↓
   hub.emit()  → SSE → 前端实时刷新
```

### 3.4 并发模型

参考实现验证过的模型，直接沿用：

- **1 个生产者线程** + `ThreadPoolExecutor(frames.workers)` 并发抽帧。
- `queue.Queue(maxsize = ai_workers * 4)` 做背压，防止抽帧把内存打爆。
- **N 个 AI 消费者线程**（`runtime.ai_workers`），视觉模型是瓶颈，并发数按显存调。
- **转写串行**（`_whisper_lock`）：本地 Whisper 独占 GPU，并发没意义还爆炸显存。
- **熔断**：连续失败 5 个文件 → 自动停止任务并广播原因。防止配错地址后刷屏重试几万次。
- **停止语义**：`StopToken`（`threading.Event`）只在文件边界检查；正在跑的文件跑完，已完成的结果保留。不做强杀，避免留下半截文件。

### 3.5 事件与日志

`hub.py` 提供三件事：

1. **环形日志缓冲**（最多 1000 条）：新客户端连上 SSE 时先补发历史，不会看到空白。
2. **SSE 广播**：每个订阅者一个 `asyncio.Queue`。管道线程通过 `loop.call_soon_threadsafe` 投递，避免跨线程操作事件循环。
3. **任务状态快照**：`GET /api/state` 返回完整状态（队列 + 任务 + 统计 + 审批），前端刷新后一键恢复。

事件类型：`log` / `task` / `file` / `stats` / `review` / `service` / `download`。

## 4. 关键实现要点（来自已验证的参考实现）

这些是**实测踩出来的结论**，重写时必须照做，否则会踩同样的坑。

### 4.1 ffmpeg 抽帧：逐时间点，不是 fps 抽样

```bash
ffmpeg -y -nostdin [-hwaccel <hw>] -ss <秒.毫秒> -i <video> \
  -frames:v 1 -vf scale=N:N:force_original_aspect_ratio=decrease \
  -q:v 5 -f image2 pipe:1
```

- `-ss` 必须在 `-i` **之前**（快速 seek，否则每个时间点都要解码整段）。
- 输出到 stdout（`pipe:1`），返回值 > 1024 字节才算成功。
- 时间点选取：极短视频（<10s）取 `[0, dur/2, dur-0.1]`；有关键帧时间戳则等距采样；否则按 `dur*(i+1)/(n+1)` 均分。
- 一帧都没抽到 → 用 `ts=0.0` 重试一次。
- `-hwaccel` 默认 `none`：1080p 素材上硬解反而更慢且不稳（产品文档里也标了「1080p 建议关闭」）。

### 4.2 ffprobe：两路调用

```bash
# 一路：时长 / creation_time / 分辨率 / 关键帧时间戳
ffprobe -v quiet -print_format json -select_streams v:0 -skip_frame nokey \
  -show_entries format=duration:format_tags=creation_time:stream=width,height,codec_name,codec_type:frame=pts_time <video>

# 二路：完整流列表（权威判定有没有音轨）
ffprobe -v quiet -print_format json -show_streams -show_format <video>
```

`creation_time` 含 `"0000"` 视为无效（很多设备写 `0000-00-00`）。

### 4.3 exiftool：写元数据分两遍，编码不同

**这是最容易出错的地方。**

| 遍次 | 写哪些标签 | ArgFile 编码 | 原因 |
| --- | --- | --- | --- |
| 第 1 遍 | `ItemList:*` / `XMP-*` | **UTF-8** | 这两处规范就是 UTF-8 |
| 第 2 遍 | `Keys:*`（QuickTime 盒） | **GBK** | Windows 属性面板按系统 ANSI 解码 Keys 盒 |

- `-charset exiftool=` 只认 `Latin/UTF8`，**不认 cp936**，所以编码必须靠「ArgFile 用什么字节写」控制。
- 文件路径**必须作为独立 argv 参数**，不能写进 ArgFile；`-@` 与路径必须是两个独立参数。
- 优先 `exiftool_files/perl.exe exiftool.pl -@ <argfile> <video>`，规避 `exiftool(-k).exe` 的 `-- press ENTER --` 挂起。
- 读取（判软水印）与写入相反：ArgFile 用 UTF-8 且**要带** `-charset filename=UTF8`。

### 4.4 SRT 与单行字数

服务端（Qwen3-ASR）已按 `max_chars` 断好行并返回 zip（含 `single_全员.srt` + 词级 `时间.json`）。客户端只在两种情况下自己重排：

1. 解析出的行平均显示宽度 < 10（CJK 计 2、西文计 1）→ 说明服务端没断行；
2. 完全没解析出 segment。

重排算法：按 `max_chars` 字数上限 / 句末标点（`。！？!?…；;`）/ 说话人切换 / 静音间隔 0.8s 切行。
本地 Whisper 路径不做字数切分：一条 segment 一行。

### 4.5 Qwen3-ASR 的 Gradio 契约

服务端函数签名（`Qwen3_ASR/app/main.py`）：

```python
def single_handler(file, lang, diarize, max_c, punc, hotwords)
# 返回 (状态Text, 完整文本Text, SRT预览Code, 结果File/zip)
```

客户端：

```python
Client(base).predict(handle_file(wav), lang_cn, bool(diarize),
                     max(5, max_chars), bool(punc), hotwords or "",
                     api_name="/single_handler")
```

- **同步阻塞**，不是轮询。超时设 600s（长素材很慢）。
- 语言映射：`auto→"自动识别"`、`zh→"Chinese"`、`en→"English"`、`yue→"Cantonese"`。
- 连通性探测：`GET {base}/config`，检查 `dependencies[].api_name` 里含 `single_handler`。

### 4.6 视觉大模型请求

OpenAI 兼容（llama.cpp server 走这条路）：

```python
messages = [
  {"role": "system", "content": system_prompt},
  {"role": "user", "content": [
      {"type": "text", "text": prompt + 辅助信息},
      {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,..."}},  # 每帧一个
      ...
  ]},
]
kwargs = dict(model=..., messages=..., timeout=..., max_tokens=...,
              temperature=..., top_p=...)
if enforce_json_mode:
    kwargs["response_format"] = {"type": "json_object"}
```

- 图片用 **base64 data URL**，多帧就是 content 数组里多个 `image_url` 对象。
- 辅助信息（原始文件名 / 时长 / 转写文本 >1200 字截断）拼在文本里。
- 解析：`re.search(r"\{.*\}", raw, re.DOTALL)` 剥离 markdown 代码块 → `json.loads` → 取 `title/plot/tags`。`title` 为空判整条失败。
- 重试：连接/超时/限流/5xx 才重试，退避 `min(2*(n+1), 8)` 秒。

### 4.7 命名与跳过

- 模板占位符：`{date}` `{title}` `{original}` `{marker}`，未知占位符原样保留。
- 日期来源优先级：`creation_time` → 文件 `min(mtime, ctime)` → 当前时间。
- 非法字符：`[<>:"/\\|?*\x00-\x1f\x7f]` → `_`；空白折叠成 `_`；Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）加后缀。
- 撞名：追加 `_1/_2/...`（上限 100）。
- **跳过已处理**（两个条件任一命中）：
  1. 文件名去掉扩展名后匹配 `(?:^|_)AI_RENAMED(?:_|$)`（词边界，不是子串）；
  2. exiftool 读到的 `Software` 标签含 `AIVideoRenameV1`（软水印）。
- 落盘用 `os.replace`（原子），可保留原时间戳。

### 4.8 Windows 工程细节

```python
CREATE_NO_WINDOW = 0x08000000          # 不弹黑框
env["PYTHONIOENCODING"] = "utf-8"
env["LC_ALL"] = "C"                    # 消除 perl locale 警告
stdout.decode("utf-8", errors="replace")
```

- 长路径：`\\?\` 前缀（UNC 用 `\\?\UNC\`），所有文件操作都过一层。
- `HF_HUB_DISABLE_XET=1`：新版 huggingface_hub 走 Xet 协议会对 hf-mirror 报 `CAS Client Error`。
- `HF_HUB_DISABLE_SYMLINKS=1`：Windows 无开发者模式建不了符号链接。

## 5. 内置 AI 服务管理（`services.py`）

本项目的差异点：**后端负责拉起 AI 服务**，用户不用开终端。

### 5.1 llama-server

```bash
AI/llama-b12412-bin-win-cuda-13.5-x64/llama-server.exe \
  -m AI/models/Qwen3.8-9B/Qwen3.8-9B-distill-heretic_nvfp4_q4_k_m.gguf \
  --mmproj AI/models/Qwen3.8-9B/mmproj-BF16.gguf \
  --host 127.0.0.1 --port 8084 \
  -c 8192 -ngl 99 \
  -np 1 --cache-ram 1024
```

两个参数是踩坑换来的，不要删：

| 参数 | 默认值 | 为什么必须显式给 |
| --- | --- | --- |
| `-np 1` | 4 | 每个槽都按 `ctx_size` 预留一份 KV cache。9B + 4 槽 + 8k 上下文在 12 GB 卡上直接 OOM，实测 `CUDA error: out of memory` 后进程退出。 |
| `--cache-ram 1024` | 8192 | 提示词缓存吃的是**系统内存**。16 GB 内存的机器上，模型 + mmproj + ASR 一起驻留时分配不出 8 GB，日志刷 `failed to allocate memory for prompt cache state: bad allocation` 后退出。 |

### 5.2 Qwen3-ASR

Qwen3_ASR 是独立项目（`D:\qita\ai\Qwen3_ASR`），有自己的便携 Python（`WPy64-312101`）和 `一键启动WebUI.bat`。后端按顺序尝试：

1. 配置里显式指定的 `python`；
2. 目录内的 `WPy64-*/python-*/python.exe`；
3. 目录内的 `一键启动WebUI.bat`；
4. 当前解释器（需要 torch，通常不可用）。

### 5.3 生命周期

| 状态 | 判定 |
| --- | --- |
| `running` | 端口可达且健康检查通过 |
| `starting` | 进程已起，健康检查未通过（模型加载中） |
| `stopped` | 无进程且端口不可达 |
| `error` | 进程已退出（记录 returncode 与 stderr 尾部 30 行） |

- **只管理自己拉起的进程**：如果端口上已有服务（用户手动开的），标记为 `external`，不杀。
- 健康检查：llama.cpp → `GET /v1/models`；Qwen3-ASR → `GET /config`。
- 启动日志实时推 SSE，前端能看到「加载模型中…」而不是干等。
- 进程退出时，从日志尾部匹配已知崩溃原因，翻译成中文建议一起塞进 `message`
  （显存不足 / 内存不足 / 端口占用 / 模型加载失败 / CUDA 驱动），前端直接显示，用户不用读英文栈。

### 5.3.1 串行拉起，不并行

两个服务都要往同一块显卡里塞模型。**并行启动时谁先抢到显存谁活，另一个随机崩**。
所以 `ensure_running()` 严格串行：先 llama，等到健康检查通过（最长 240 s），再起 ASR。
这样失败方永远是后起的转写服务，视觉这条主链路（没它就没产品）保证可用。

### 5.3.2 任务结束即回收（`services.stop_after_task`，默认开）

整批文件落盘后，显存没有任何理由继续被占着：

```text
开始任务 → engine._run() 先 ensure_running()（服务没开就拉起来）
         → 逐文件处理
         → 全部落盘 → 后台线程 services.stop_after_task() → 只停本程序拉起的进程
下次开始任务 → 再次 ensure_running() → 自动拉起
```

- 关掉这个开关（设置 → AI 服务 → 启动行为）则服务常驻，连续跑多批时少一次模型加载等待。
- `external` 进程永远不动。
- 12 GB 显存 / 16 GB 内存这类机器，默认配置就是「若不并发就都不并发」：单批任务里两个服务仍可能同时用卡，
  所以默认抽帧降到 4 帧 @512（见 §11），并在设置页对 ≤12 GB 的卡显示显存提示。

## 6. 「一键补齐 AI 依赖与模型」（`bootstrap.py`）

### 6.1 清单化自检

`GET /api/bootstrap/check` 返回清单：

| 项 | 判定 | 缺失后果 |
| --- | --- | --- |
| llama.cpp 二进制 | `llama-server.exe` 存在 | 无法视觉分析 |
| 视觉模型 GGUF | 文件存在且大小合理（>1GB） | 同上 |
| mmproj | 文件存在 | 无视觉能力 |
| Qwen3-ASR 模型 | 目录含 `model.safetensors` | 无法转写 |
| ForcedAligner | 目录含 `model.safetensors` | 无词级时间轴 |
| ffmpeg / ffprobe | 仓库内或 PATH | 全流程不可用 |
| exiftool | 仓库内或 PATH | 元数据不可用 |
| Python 依赖 | `importlib.util.find_spec` | 启动失败 |

### 6.2 下载

- 走 HF 镜像（`runtime.hf_endpoint`，默认 `hf-mirror.com`）。
- **自实现 Range 续传**：断流从已有字节接续，`model.bin.incomplete` 与正式文件取较大者继续；`416` 视为已完成，`401/403/404` 立即失败不重试，`429/5xx` 退避重试。
- 进度（已下载/总量/速度/剩余时间）推 SSE。
- 下载完校验大小 + 可读性，再原子改名到最终路径。

### 6.3 开关

- `bootstrap.auto_check`：启动时自动自检（默认开，只读不下载，很快）。
- `bootstrap.auto_fetch`：缺失时自动下载（**默认关**，因为总量约 10.4 GB，不该在用户不知情时吃带宽）。
- 设置页有对应开关 + 一个「立即补齐」按钮。

## 7. 前端接线

现有 `前端/js/*.js` 是**全模拟**的（`setInterval` 假进度、假日志、假审批）。接线方案：

### 7.1 新增 `js/api.js`

统一后端客户端：

```js
VAIR.api = {
  get(path), post(path, body), put(path, body),
  dialogFiles(), dialogFolder(),          // 原生选择器，超时 15 分钟
  sse(onEvent),                            // EventSource 封装 + 自动重连
  refreshState()                           // GET /api/state 拉全量状态
};
```

### 7.2 状态来源切换

- `app.js` 的 `state` 保留为前端视图缓存，但**权威源在后端**。
- 收到 SSE `state` 事件 → 整体替换本地 state → 触发渲染。
- 连不上后端时（直接 `file://` 打开）→ 自动降级为原有的模拟引擎，原型演示仍然可用。这个降级路径要保留。

### 7.3 各页面改动

| 文件 | 改动 |
| --- | --- |
| `workbench.js` | `start()`/`stop()` 改为 `POST /api/tasks`、`POST /api/tasks/stop`；拖拽/路径改为 `POST /api/items`；假 `setInterval` 全删 |
| `realtime.js` | 从 SSE 的 `task`/`file` 事件驱动阶段进度 |
| `approvals.js` | 数据来自 `/api/reviews`；通过/忽略 → `POST /api/reviews/{id}` |
| `logs.js` | 日志来自 SSE + `/api/logs`；时间线来自 `/api/state` |
| `settings.js` | 启动时 `GET /api/config` 回填所有控件；改动 `PUT /api/config`；新增 AI 服务面板与补齐面板 |
| `index.html` | 设置页按第 8 节补齐全部配置项 |

## 10. 安全与健壮性

- 配置坏了（JSON 解析失败）→ 回退默认值启动并告警，不让服务起不来。
- 所有外部命令走统一 `proc.run()`：超时、UTF-8、隐藏窗口、异常转 `ToolError`。
- 路径穿越防护：静态文件路由 `normpath` 后校验仍在静态目录内。
- `dry_run` 时**所有写操作短路**（改名 / NFO / SRT / 元数据 / `_failed` 移动），保证预览模式下磁盘零改动。
- 上传/下载产物写入独立临时目录，用完即删。
- 局域网模式下 `PUT /api/config`、文件选择器、服务启停等写操作**已落地**中间件拦截：
  `_locality_guard` 对 `POST/PUT/DELETE /api/config`、`/api/dialog/*`、`/api/services/*`、`/api/bootstrap/*` 等
  检查 `request.client.host`，非本机返回 `403`；GET 全部放行，手机端可只看与审批。

## 11. 性能预算（RTX 5070 12GB 基准）

默认参数按「显存小的机器也能跑」定：**4 帧 @512px**、`ai_workers=2`、`-np 1`、`--cache-ram 1024`。

| 阶段 | 实测（30 MB / 3 分钟素材） | 目标 |
| --- | --- | --- |
| ffprobe | 0.3s | < 1s |
| 抽 4 帧 @512px | 0.2s | < 1s |
| 远程 Qwen3-ASR | 2.5s | < 15s |
| 视觉模型分析（4 帧 @512px） | 9.5s | < 20s |
| 落盘（改名 + NFO + SRT + exiftool） | < 2s | < 2s |
| **端到端（单文件）** | **约 13s**（不含服务加载） | **< 90s** |

模型加载要另算：llama.cpp 约 20s，Qwen3-ASR 约 40s。所以「一批任务」的首个文件会明显慢，
批次之间如果开着 `stop_after_task`，每批都要重新付一次加载成本；连续跑多批建议关掉该开关。

12 GB 卡上**不要同时**让两个服务做推理：ASR 峰值独占约 7.3 GB，llama 约 6 GB，合计超卡。
实测两者并行时 ASR 抛 `torch.OutOfMemoryError`。默认抽帧降到 4 帧 @512 后提示词大幅变小，
多数素材能挤下；仍 OOM 时按设置页的显存提示先关掉一个服务。

## 12. 验证方式

1. **离线链路**：断网，拖入真实 MP4，跑通全流程并产出正确文件名 + NFO + SRT + 元数据。
2. **预览模式**：磁盘零改动（前后对比文件 mtime 与内容哈希）。
3. **补齐**：临时改名 `AI/models` 目录，点「立即补齐」，验证能下载回来并跑通。
4. **设置持久化**：改设置 → 重启后端 → 设置仍在。
5. **远程访问**：手机连同一 Wi-Fi 打开，能看进度、能审批。
6. **异常路径**：AI 服务未启动、转写服务挂掉、素材无音轨、文件名含非法字符、目标目录只读。
7. **不回归**：`file://` 直接打开 `前端/index.html` 时原型演示仍可用（降级路径）。
