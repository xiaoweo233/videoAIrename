# 启动降级 · 技术设计

## pip 引导

启动器检测便携版 `python.exe` 后，必须额外用 `python -m pip --version` 判断可用性。缺 pip 时先尝试最新版官方 get-pip.py；失败后通过国内 simple 索引取得适用于 Python 3.12 的 pip wheel 链接及 SHA-256，下载并校验后解压到项目内的 `python/Lib/site-packages`。无系统安装操作。索引与下载失败时不要放弃后续降级服务。

## 服务分层

- 标准层：FastAPI / Uvicorn 和四项核心模块可用，正常加载完整应用。ffmpeg 可缺失，但自检 `ok=false`，处理视频前仍由现有媒体探测路径报告具体错误。run.py 自动补 ffmpeg 的网络操作失败不能成为阻塞条件。
- 诊断层：四项核心模块任意缺失时，基于 Python 标准库 `http.server.ThreadingHTTPServer`，只绑定 `127.0.0.1`，固定精简路由 `/` 与 `/api/health`、`/api/diagnostics`、`/api/retry`。静态帮助页说明不可处理视频及重试动作；重试不能让阻塞 HTTP 线程失去响应，成功后提示重新启动。不得挂载真实工作台、配置或其他敏感接口。
- 自检 `--selfcheck` 始终只输出状态而不启动，也不自动下载。

## 回归

用独立的临时项目根与依赖探测替身模拟：缺 pip、核心依赖失败、ffmpeg 缺失、正常就绪四条路径；检查诊断服务能响应 HTTP、拒绝外部监听、重试失败仍可用。不要修改用户的 `config.json` 或对真实用户视频做写操作。
