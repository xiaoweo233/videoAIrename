# VAIR · 视频 AI 重命名助手

把一堆手机拍回来的视频（`VID_20260801_190533.mp4` 这种）丢进去，
本地大模型自己看画面、听内容，然后改成能看懂的日期化文件名，并补齐 NFO / SRT / 元数据。

**全本地跑，不联网、不上传。** 视觉用 llama.cpp + Qwen3.8-9B，转写用 Qwen3-ASR。

---

## 先看这个：需要什么机器

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64（当前版本只在 Windows 上验证过） |
| 显卡 | NVIDIA，**≥ 8 GB 显存**；12 GB 是舒适线，8 GB 需调小抽帧数 |
| 内存 | ≥ 16 GB（llama.cpp 的提示词缓存吃系统内存） |
| 磁盘 | 约 11 GB 给 AI 资产 + 视频本身的临时空间 |
| Python | 3.10+；**没装也行** —— 双击 `start.bat` 会自动在项目里放一个便携版 |

> 显存不够时不要同时开视觉和转写两个服务：设置页会按显卡显存给出建议值。

## 最快的跑法：双击 `启动.bat`

```bat
启动.bat              等价于「双击」：没有 Python 就装便携版，然后启动
启动.bat --lan        局域网可访问（手机连同一 Wi-Fi）
启动.bat --port 8080  换端口
启动.bat --selfcheck  只打印环境自检报告，不启动
启动.bat --setup-python  只准备便携版 Python，不启动
```

它做完这些事：找 Python → 没有就问你一句、从国内镜像下 **便携版**（11 MB，解压到 `项目\python\`，
不写注册表、不装进 C 盘、不需要管理员权限，整个文件夹拷到别的电脑照样能跑）→ 顺手把 pip 装进去 →
启动后端；缺 ffmpeg / exiftool 也会在这一步自动补上（见下）。

> 启动逻辑写在 `start.ps1` 里（UTF-8 + 中文），`启动.bat` 只是一个纯 ASCII 的两行外壳。
> 这样做是因为 cmd.exe 解析批处理时会被中文和 `chcp` 搞乱字节偏移（详见 `start.ps1` 开头的注释）。

已经装好 Python 3.10+ 的话，也可以照旧手动跑（见文末「开发」）。

## 三步跑起来

1. **放 AI 资产**（约 10.4 GB，**不入库**，clone 下来是空的）
   模型和推理引擎因为体积太大没有进仓库，第一次用必须补齐。两种方式：

   - 打开页面 → 设置 → 系统 → 点「**补齐 AI 依赖与模型**」，自动下载缺的（走 HF-Mirror，支持断点续传）。
   - 或自己按下面的结构放好：

   ```text
   AI/
     llama-b12412-bin-win-cuda-13.5-x64/llama-server.exe   # llama.cpp CUDA 版
     models/
       Qwen3.8-9B/
         Qwen3.8-9B-distill-heretic_nvfp4_q4_k_m.gguf      # 视觉模型 4.82 GB
         mmproj-BF16.gguf                                  # 视觉投影层 0.86 GB
       Qwen/
         Qwen3-ASR-0.6B/                                   # 转写 1.75 GB
         Qwen3-ForcedAligner-0.6B/                         # 词级对齐 1.71 GB
   ```

   另外 `ffmpeg/`、`exiftool/` **不用自己找**：启动时缺哪个就自动下哪个（ffmpeg 约 115 MB、exiftool 约 11 MB，
   直接从网上拉，不经过模型仓库），只有一次；想手动放也行，放进仓库根目录的 `ffmpeg/`、`exiftool/` 就会被自动发现。

   Qwen3-ASR 是独立项目，默认从 `../Qwen3_ASR` 找（自带便携 Python）。
   放在别处就在设置 → AI 服务 → 转写服务里改「项目目录」。

2. **启动后端**：双击 `启动.bat`，或者手动

   ```bat
   cd 后端
   python run.py
   ```

   首次启动会自动把缺失的 Python 依赖装进 `后端/libs/`。控制台会打印本机与局域网访问地址。
   所有下载（模型、ffmpeg、依赖）都是**多连接分片 + 断点续传**：断了重跑会接着下，不会从头再来。

3. **打开浏览器**访问 `http://127.0.0.1:8000/`，把视频拖进工作台，点「开始处理」。

   > 拖拽和「选择文件 / 选择文件夹」按钮都行。从资源管理器拖入时浏览器只会给一个
   > `file:///…` 形式的地址，后端会把它还原成本地路径；如果浏览器连这个都不给
   > （某些情况下会这样），就用按钮，或者直接把路径粘进输入框。

## 第一次用，建议这么走

1. 设置 → 命名与输出 → 打开「**预览模式**」。
2. 处理一两个视频，去「命名审批」页看 AI 起的名字对不对。
3. 不满意就改提示词（设置 → AI 与提示词）或补术语表（设置 → 术语表）。
4. 满意后关掉预览模式，正式批量跑。

## AI 服务是怎么被管起来的

- 启动后端时按配置**自动拉起**（可在设置里关）。
- 拉起是**串行**的：先视觉、就绪后再转写——同时起会抢显存，随机崩一个。
- **整批任务落盘完成后自动关闭**（`设置 → AI 服务 → 启动行为 → 处理完成后关闭 AI 服务`，默认开），
  把显存和内存还给系统；下次点开始处理会自动重新拉起。
- 只停自己拉起的进程。你手动开的服务会被标成「外部进程」，本程序不会去杀。
- 服务崩了会直接给中文原因（显存不足 / 内存不足 / 端口占用 / 模型缺失），并给可操作的调整建议。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 服务状态「显存不足」 | 两个服务同时占了卡。设置里把「并发槽数」设 1、「上下文长度」降到 4096，或先停掉转写服务只跑视觉 |
| 服务状态「内存不足（提示词缓存分配失败）」 | 系统内存不够。把「提示词缓存上限」调到 512–1024 |
| 转写提示「转写服务没在运行」 | 刚跑完一批任务，服务已按设置释放；下次开始任务会自动拉起，也可在设置里手动启动 |
| 抽帧失败 | 检查 `ffmpeg/ffprobe` 是否在仓库目录或 PATH（启动时会自动补） |
| 元数据写不进去 | 检查 `exiftool/` 是否存在；文件是否被别的程序占用 |
| 下载模型很慢 / 总是断 | 默认 4 路并发 + 断点续传。想排查可以设 `VAIR_DOWNLOAD_CONNECTIONS=1` 退回单线程 |
| 局域网手机打不开 | 设置 → 系统 → 打开「局域网访问」；Windows 防火墙需放行该端口 |
| 端口被占用 | 设置 → 系统里改端口，或 `python run.py --port 8081` |
| 删掉项目里的 `python\` 会怎样 | 什么都不会坏，下次双击 `start.bat` 会重新放一个 |

局域网模式下，改配置、选文件、启停服务这类操作只允许本机发起，远程只能查看进度和审批（返回 403 是有意为之）。

## 目录

```text
启动.bat    Windows 一键启动（纯 ASCII 外壳，只负责调 PowerShell）
start.ps1   真正的启动逻辑：找/装便携版 Python、补 pip、再启动后端
python/     便携版 Python（启动.bat 自己下载的，不入库）
前端/       纯静态页面（玻璃风 UI），由后端直接托管
后端/
  run.py        启动入口（自检 → 装依赖 → 补外部工具 → 起服务）
  app/          核心代码：pipeline 处理链路、services 服务管理、vision/transcribe 推理、
                naming 命名、outputs 落盘、bootstrap 自检与下载、web/api.py HTTP 接口
文档/
  产品设计.md   做什么、为什么这么做
  技术设计.md   怎么实现、踩过哪些坑
```

## 开发

```bat
cd 后端
python run.py --reload            # 改代码自动重启
python run.py --no-autostart      # 不拉起 AI 服务（调试前端时省显存）
python run.py --selfcheck         # 只打印环境自检报告
```

配置是**只存差异**的：`config.json` 里只有你改过的项，没改的永远跟随代码里的默认值，
所以升级后调优过的默认参数能生效。想恢复出厂：设置 → 系统 → 恢复默认，或删掉 `config.json`。

接口文档在 `http://127.0.0.1:8000/api/docs`。
